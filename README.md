# 📧 MailingService

**Сервис для управления email-рассылками с разграничением прав доступа и детальной аналитикой доставок.**  
Позволяет пользователям создавать базы клиентов, формировать сообщения и планировать кампании, а менеджерам — контролировать процесс, управлять правами сотрудников и получать сводную статистику по всей системе.

---

## ⚙️ Функционал

### Для всех пользователей:
- **Регистрация и аутентификация:** создание аккаунта с обязательным подтверждением по email (token-based activation).
- **Управление клиентами (CRUD):** добавление, редактирование и удаление получателей с валидацией уникальности email в рамках одного аккаунта.
- **Управление сообщениями (CRUD):** создание шаблонов писем с темой и телом.
- **Управление рассылками:** планирование отправок с указанием интервала (`start_time` – `end_time`), выбор сообщения и списка получателей.
- **Мгновенная отправка:** кнопка "Отправить сейчас" с проверкой прав доступа и временного интервала.
- **Персональная статистика:** дашборд с метриками (всего рассылок, успешные/ошибочные доставки, процент успешности, уникальные получатели).

### Только для менеджеров:
- **Глобальный обзор:** просмотр всех клиентов, сообщений и рассылок в системе (независимо от владельца).
- **Управление пользователями:** просмотр списка пользователей, повышение до роли "Менеджер", блокировка и разблокировка аккаунтов.

## 🏗️ Архитектурные решения и особенности

1. **Модели данных и связи:**
   - `Client` и `Message` связаны с моделью `User` через `ForeignKey` (поле `owner`), обеспечивая изоляцию данных.
   - `Mailing` связывает одно `Message` и множество `Client` через `ManyToManyField`.
   - `MailingAttempt` логирует каждую попытку отправки (статус, время, ответ сервера), что позволяет строить точную аналитику.
2. **Multi-tenancy (Многопользовательская изоляция):**  
   Реализована на уровне ORM. В `ListView` и формах `QuerySet` динамически фильтруется по `owner=request.user`. Если пользователь состоит в группе "Менеджер", фильтрация снимается, и он видит все объекты.
3. **Кэширование производительности:**  
   Используется **Redis** для кэширования "тяжелых" запросов: списков клиентов/сообщений и статистики на главной странице (TTL 5–10 минут). Кэш автоматически инвалидируется при создании, обновлении или удалении объектов.
4. **Ролевая модель (RBAC):**  
   Права управляются через встроенные группы Django. Кастомная management-команда `create_groups` автоматически создает группы "Пользователь" и "Менеджер" и назначает им соответствующие `Permission`. Контекстный процессор `user_role` добавляет флаг `is_manager` во все шаблоны для управления отображением элементов интерфейса.
5. **Валидация:**  
   В `MailingForm` реализована кастомная валидация (`clean`), запрещающая указывать время начала в прошлом и требующая, чтобы время начала было строго раньше времени окончания.

## 🛠️ Стек технологий

- **Язык:** Python 3.11+
- **Фреймворк:** Django 5.x
- **База данных:** PostgreSQL
- **Кэширование:** Redis
- **Драйвер БД:** `psycopg2`
- **Управление зависимостями:** Poetry (или `pip` + `requirements.txt`)
- **Переменные окружения:** `python-dotenv`
- **Отправка почты:** SMTP (Yandex Mail, SSL)

## 🚀 Инструкция по запуску

### 1. Клонирование репозитория
```bash
git clone https://github.com/starchenko-dmi/MailingService.git
cd mailing-service
```

### 2. Настройка окружения
Установите зависимости с помощью Poetry (или pip):
```bash
poetry install
# или
pip install -r requirements.txt
```

### 3. Переменные окружения
Создайте файл `.env` в корневой директории на основе шаблона `.env.example`:
```env
# .env.example
DEBUG=True
SECRET_KEY=your-super-secret-key-here

# PostgreSQL
DB_NAME=mailing_db
DB_USER=postgres
DB_PASSWORD=your_db_password
DB_HOST=localhost
DB_PORT=5432

# Email (Yandex SMTP)
EMAIL_HOST_USER=your_email@yandex.ru
EMAIL_HOST_PASSWORD=your_app_password
```

### 4. Подготовка базы данных
Примените миграции и создайте суперпользователя:
```bash
python manage.py migrate
python manage.py createsuperuser
```

### 5. Инициализация ролей (Обязательно!)
Запустите кастомную команду для создания групп и назначения прав:
```bash
python manage.py create_groups
```

### 6. Запуск сервера
Убедитесь, что запущены службы PostgreSQL и Redis, затем стартуйте приложение:
```bash
python manage.py runserver
```
Приложение будет доступно по адресу: `http://127.0.0.1:8000`

## 💡 Примеры использования

1. **Регистрация:** Перейдите по ссылке `/users/register/`, введите данные. На указанный email придет письмо со ссылкой для активации аккаунта.
2. **Создание рассылки:** 
   - Добавьте клиента в разделе "Клиенты".
   - Создайте шаблон письма в разделе "Сообщения".
   - Перейдите в "Рассылки", нажмите "Создать рассылку", выберите сообщение, клиентов и укажите интервал времени.
3. **Отправка:** На странице списка рассылок нажмите кнопку "Отправить сейчас". Система проверит права и временной интервал, выполнит рассылку через SMTP и сохранит результат каждой попытки в модель `MailingAttempt`.
4. **Аналитика:** Перейдите в раздел "Статистика", чтобы увидеть конверсию и процент успешных доставок ваших кампаний.
